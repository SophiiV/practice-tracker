# Лабораторна робота 11

Вимоги: щонайменше 10 функціональних тест-кейсів (від 5 позитивних і 5 негативних), до 10 Unit-тестів, 2–3 інтеграційні перевірки, фактичні результати, дефекти і скріншоти.

Реалізовано 20 функціональних тест-кейсів: TC-01–TC-18 у `backend/tests/functional.test.js`; TC-19–TC-20 (пошук) у `ui.mjs`. Разом 8 позитивних і 12 негативних. Окремо є 6 браузерних перевірок UI-01–UI-06, 10 Unit-тестів і 3 інтеграційні тести. Попередні 38 перевірок API збережені як регресійний набір.

## Запуск

З папки backend: `npm test`, `npm run test:unit`, `npm run test:integration`.
З папки testing: `npm install`, `npm run test:ui` (Google Chrome), `python3 check_documents.py`.
Перед структурною перевіркою DOCX виконайте `npm test`: він формує тестові файли в `artifacts/`.

`ui.mjs` сам запускає API на вільному порту та Vite на 5179, використовує тимчасову БД і закриває процеси після виконання. `PYTHON_BIN` дозволяє обрати Python 3.

## Докази

- `test-output.txt`, `unit-output.txt`, `integration-output.txt`: журнали фактичних запусків.
- `functional-results.json`, `integration-results.json`, `ui-results.json`: структуровані результати.
- `baseline.txt`: поведінка старої версії до виправлень. `baseline.mjs` дозволяє повторити ті самі запити; після виправлень результати закономірно відрізнятимуться.
- `document-checks.txt`: цілісність DOCX і незмінність частин шаблонів.
- `screenshots/`: скріншоти застосунку і візуальні звіти фактичних журналів (створюються `evidence.mjs`).
- `defects.md`: опис дефектів і повторних перевірок.

Дата оформлення результатів: 19.10.2026. Тривалість тестів залежить від машини. Фактичний час запусків збережений у вихідних журналах; це локальні функціональні перевірки, а не навантажувальний аудит.
